# D1

D1 is SQLite in front of the Worker (`env.DB.prepare(...)`), persisted through celld / LTX onto **your** object store.

## Root vs child

| Version | How D1 appears |
|---------|----------------|
| **Root** (no parent) | Import / seed (empty or `celld d1 import`) |
| **Child** (`parent_version_id`) | **Branch** — copy-on-write from parent. Writes do not land in the parent |

This is the core “preview has real data” mechanism.

## In the Worker

Same shape as Cloudflare:

```js
export default {
  async fetch(req, env) {
    const { results } = await env.DB.prepare(
      'select id, name from products limit 20',
    ).all()
    return Response.json(results)
  },
}
```

Declare the database in wrangler (`d1_databases`) inside the bundle. Child versions keep the parent `database_id` so you do not rewrite code.

## Operator API

All admin-authenticated, scoped to a version:

| Call | Use |
|------|-----|
| `GET …/database` | Summary |
| `GET …/database/tables` | Table list |
| `GET …/database/tables/{name}/rows` | Browse |
| `POST …/database/query` | SQL (`{ "sql": "…" }`) |

Dashboard → Storage → D1 browser is the same API.

`503` means that version’s celld is not serving (archived, still deploying, or crashed).

## Seeding locally

```bash
./dev/scripts/seed-commerce-store.sh
```

That path imports ecommerce-shaped SQL into `commerce-store` `v1`. For your app, ship a seed as part of first-version bring-up (CI job or operator script), not as a JSON blob in the REST body — the import contract is file/CLI based on purpose.

## What not to expect

- Cross-version “sync from prod” button — branch at deploy time instead
- Cloudflare D1 HTTP API / Time Travel product
- Sharing one D1 file across two ready versions (violates isolation)
